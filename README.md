# ВТБ Ко-пилот: Интеллектуальный ассистент и тренажер бэк-офиса

**Спринт №1 (MVP)** — Прототип системы интеллектуальной маршрутизации, строгой регламентной поддержки решений (Strict Grounding) и интерактивного тренажера-песочницы для обучения стажеров бэк-офиса банка ВТБ.

---

## 🐳 Запуск через Docker (рекомендуется)

Нужен Docker с Compose v2 или новее (например, Docker Desktop). Go и Node.js на хосте не нужны.
Из корня репозитория подготовьте `.env` по образцу `.env.example` и укажите
`GEMINI_API_KEY` (ключ Google AI Studio). Если `.env` уже существует, дополните его.
Затем:

```sh
docker compose up -d --build --wait
```

Интерфейс: [http://localhost:8080](http://localhost:8080).
При запуске на сервере замените `localhost` его IP-адресом или именем.
API доступен через тот же адрес: [демо-кейсы](http://localhost:8080/api/v1/cases),
[проверка API](http://localhost:8080/api/health).

Compose собирает Go API с демо-данными и React-интерфейс, который раздается через Nginx.
Nginx проксирует `/api/` в бэкенд; порт бэкенда наружу не публикуется.
Поиск работает локально, генерация резолюций обращается к Gemini API.
Без ключа поиск продолжает работать, ко-пилот безопасно эскалирует заявку,
а песочница сообщает, что ответ пока не оценён.
Отдельная база данных не нужна. Первая сборка требует доступа к реестрам Docker,
Go и npm; для генерации нужен исходящий HTTPS-доступ к `generativelanguage.googleapis.com`.

```sh
docker compose ps                # состояние и healthcheck
docker compose logs -f          # логи (Ctrl+C — выйти из просмотра)
docker compose down             # остановка и удаление контейнеров
docker compose up -d --build --wait  # пересобрать после изменений кода или data/
```

Чтобы изменить внешний порт, создайте в корне файл `.env` со строкой `APP_PORT=3000`
и запустите ту же команду. Тогда интерфейс будет доступен на `http://localhost:3000`.

## 🎯 Основной функционал

### Поиск по нормативным чанкам

При старте API загружает все объекты `chunks` из `backend/data/rules.json`
(в текущем файле — 112) и строит неизменяемый индекс в памяти. По умолчанию
файл ищется рядом с `demo_cases.json`; путь можно переопределить переменной
`RULES_PATH`. Отсутствующий или некорректный файл останавливает запуск API.
После изменения нормативной базы нужно перезапустить API, а при использовании
Docker — пересобрать образ командой запуска выше.

Go-функция: `(*search.Index).Search(ticket string) domain.SearchResult`
в `backend/internal/search/index.go`. Создание индекса:
`search.Load(path, search.DefaultThreshold)`. Внешние модели и векторная БД не нужны.
Используется комбинация косинусного сходства TF-IDF-векторов (65%) и взвешенного
покрытия токенов запроса (35%). Учитываются стоп-слова, русские словоформы через
сопоставление первых шести букв длинных слов, `ё/е`, варианты дефиса и суммы
`5 000 000` / `5000000`. Одиночное совпадение в многословном запросе получает
понижающий коэффициент 0.5.

```sh
curl http://localhost:8080/api/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"text":"Неверный ИНН КПП получателя, ошибка в БИК"}'
```

Ответ содержит `chunks` (до трёх объектов с исходными `text`, `citation`, `id`
и индивидуальным `score`), `best_score` и `escalation_required`.
Возвращаются только чанки с положительным score: при отсутствии совпадений
массив пустой, искусственно дополнять выдачу до трёх источников система не будет.
Если лучший score ниже `search.DefaultThreshold` (сейчас 0.20), выставляется
`escalation_required=true`. Порог — начальная эвристика, требующая проверки на
размеченных банковских заявках; score не является вероятностью правильного решения.

В `/api/v1/copilot/resolve` проверка выполняется до обращения к модели:
нерелевантный текст сразу эскалируется даже при переданном `case_id`.
Ответ дополнен `retrieved_chunks` и `retrieval_score`; поле `sources` содержит
только выбранные моделью и проверенные сервером цитаты. В ответе fallback это
найденные кандидаты для проверки экспертом. Даты редакций в `rules.json`
отсутствуют, поэтому `edition_date` остаётся пустым.

Проверки из директории `backend`:

```sh
go test ./internal/search
go test ./internal/llm
go test ./internal/handler -run 'Test(Health|GetDemo|CORS|Copilot|Search)'
go test ./internal/search -bench BenchmarkSearch -run '^$'
go vet ./...
```

Полный набор проверок: `go test ./...` и `go vet ./...`.

### Генерация резолюций через Gemini

Клиент `backend/internal/llm/gemini.go` использует официальный REST API
`models.generateContent`. По умолчанию — `gemini-3.5-flash-lite`, для которого
Google указывает бесплатный тариф с ограничениями. Доступ и квоты зависят от
проекта; приложение не включает биллинг и не переключается на другую модель.
Справка: [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite),
[тарифы](https://ai.google.dev/gemini-api/docs/pricing),
[структурированный вывод](https://ai.google.dev/gemini-api/docs/structured-output).

Настройки в корневом `.env`:

```dotenv
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_TIMEOUT=25s
```

Compose передаёт их только бэкенду. При локальном запуске API автоматически
загружает ближайший `.env`, поднимаясь от рабочей директории к корню файловой
системы: `cd backend` и `go run ./cmd/api` находят корневой `.env` репозитория.
Переменные окружения процесса имеют приоритет; отсутствие `.env` допустимо.
Некорректный `.env` останавливает запуск с сообщением об ошибке.
Ключ не входит в образы и не передаётся фронтенду. Не коммитьте `.env`.
Для прототипа используйте синтетические заявки: Gemini — внешний сервис,
которому передаются текст заявки и найденные фрагменты нормативной базы.
Это облачный режим демонстрации, а не изолированное on-premise развёртывание.

Промпты аналитика сохранены в `backend/internal/llm/system_prompt.txt`
(боевой режим) и `backend/internal/llm/sandbox_prompt.txt` (наставник).
Файлы встраиваются в бинарник; после изменения пересоберите API.
Плейсхолдеры `{context}`, `{task}`, `{trainee_answer}` заполняются сервером;
пользовательские данные экранируются, чтобы не закрыть XML-разделы промпта.

```sh
curl http://localhost:8080/api/v1/copilot/resolve \
  -H 'Content-Type: application/json' \
  -d '{"task_text":"Неверный ИНН КПП получателя, ошибка в БИК"}'
```

Модель отвечает по исходной схеме промпта: `task_type`, `route`, `resolution`,
`citations`, `confidence`, `escalation_brief` и другие поля. Полный результат
возвращается в `analysis`, а совместимые поля `suggested_route`, `resolution_draft`,
`sources` сохраняются для интерфейса. `sources.quote` сервер берёт из исходных
чанков по проверенному идентификатору, а не генерирует заново.
Категории уверенности отображаются в старом числовом поле как 0.9 / 0.6 / 0.2;
это условное отображение категорий, не измеренная вероятность.
Сервер проверяет JSON, обязательные поля, ссылки, ограничения длины и согласованность
эскалации с низкой уверенностью, пустыми действиями и передачей руководителю смены.
Проверка структуры и ссылок не доказывает правильность каждого вывода модели;
резолюцию должен проверить сотрудник.

При таймауте (по умолчанию 25 секунд, допустимо до 30), ошибке сети, отсутствии
ключа, HTTP 429/5xx, блокировке, обрезанном ответе, неверном JSON или выдуманной
цитате API возвращает HTTP 200 с `escalation_required=true`, `confidence_score=0`
и безопасным сообщением передачи эксперту. Повторные попытки автоматически не
выполняются. Ключи, заявки и ответы провайдера в логи не записываются.

### Наставник песочницы

`POST /api/v1/sandbox/evaluate` принимает `case_id` и `trainee_answer`
(либо совместимое поле `trainee_solution`). Сервер выбирает карточку из
`demo_cases.json`, передаёт модели эталон, типичные ошибки, критерии и полные
тексты пунктов из `expected_rule`. Подменить эталон или условие через запрос нельзя.
Эталоны и критерии проверки не публикуются в `/api/v1/cases`.

```sh
curl http://localhost:8080/api/v1/sandbox/evaluate \
  -H 'Content-Type: application/json' \
  -d '{"case_id":"SANDBOX-01","trainee_answer":"Запрос до 19.10.2026, уточнение до 22.10.2026. Если ответа нет, платёж возвращается. Исполняет L1."}'
```

Полная схема промпта возвращается в `evaluation`: `criteria_results`,
`missed_points`, `errors_found`, `critical_error`, `passed`, `main_lesson`, `flags`.
Старые `score`, `feedback`, `is_correct`, `missed_rules` заполняются для интерфейса.
Сервер проверяет порядок критериев, их максимумы, сумму баллов, вердикты,
ссылки на регламент и связь `passed = score >= 7 && !critical_error`.
Полный эталон не возвращается в ответе и не вставляется в разбор.

Если карточка, эталон или критерии отсутствуют, API возвращает HTTP 422
с `error=missing_context`. При сбое модели — HTTP 200,
`evaluation_unavailable=true`, `escalation_required=true`, без объекта `evaluation`;
интерфейс показывает «Ответ пока не оценён», без оценки 0/10. Задания без карточки
не получают выдуманную оценку по длине ответа.

### 1. Боевой режим (Ко-пилот бэк-офиса)
* **Интеллектуальная маршрутизация**: Определение подразделения и уровня ответственности (L1, L2, L3) на основе регламентных признаков.
* **Черновик регламентной резолюции**: Генерация готового решения инцидента с пошаговым алгоритмом и указанием сроков SLA.
* **Strict Grounding**: Каждое действие подтверждается точной цитатой и пунктом нормативно-правового документа (регламенты REG-01, REG-02, 161-ФЗ, 762-П Банка России).
* **Индикатор уверенности (Confidence Score)**: Оценка надежности сформированного ответа и автоматический триггер эскалации на уровень L3 при нестандартных ситуациях.

### 2. Песочница стажера
* **Интерактивный тренажер**: Проверка решений стажеров по реальным инцидентам бэк-офиса.
* **Оценка по 10-балльной шкале**: Быстрый вердикт ("Успешно", "Требует доработки", "Не пройдено").
* **Разбор ошибок наставником**: Подробный анализ нарушений протоколов идентификации, правил СБП и кредитной политики.
* **Упущенные регламенты**: Четкий список нарушенных или забытых пунктов правил.
* **Эталонное решение**: Демонстрация стандарта работы банка ВТБ для закрепления знаний.

### Тексты правил для Drawer

- `GET /api/v1/rules` — полный JSON-массив чанков в порядке `rules.json`.
- `GET /api/v1/rules/REG-01-1.4` — один чанк с полями `id`, `document`,
  `document_title`, `section`, `section_title`, `clause`, `citation`, `text`.
- Неизвестный `id` — HTTP 404, `{"error":"rule_not_found"}`.

Локальный адрес API: `http://localhost:8000`; через Docker — `http://localhost:8080`.
Например, `GEN-5.2` открывает пункт запрета на раскрытие критериев проверок.

До обращения к Gemini песочница проверяет ответ стажёра на маркеры
«система антифрода», «подозрительный получатель», «порог суммы», «обойти блокировку»
(без учёта регистра, с поддержкой склонений и пробельных символов).
Любое совпадение, в том числе в цитате или отрицании, приводит к HTTP 200,
`score: 0`, `is_correct: false`, `evaluation.critical_error: true` и ссылке
`GEN, п. 5.2` в `missed_rules` и разборе ошибки. Это консервативная проверка
маркеров, а не смысловой анализ. Она работает и без ключа Gemini;
для неизвестной карточки сохраняется HTTP 422 `missing_context`.
